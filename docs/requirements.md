# 总体题目与验收要求

## 1. 题目

设计并实现一个“双轮 + 左右四连杆腿”的小型轮腿机器人系统。整机原则上不超过 300 mm × 300 mm × 300 mm，采用 6 电机（每侧两个腿部电机、一个轮足电机）。机身可用长方体、无人机无刷电机可用圆柱体近似；上杆、下杆、销钉/环状转动副和轮足连接必须可检查。参赛者可自行决定连杆长度、轮径、轮距、机身尺寸、电机安装方式、关节位置、轮轴位置和关节限位，但必须说明设计依据并满足运动学合理性。详见 [`wheelleg_geometry.md`](wheelleg_geometry.md)。

## 2. 必须形成的链路

机械 CAD → URDF/Xacro → 动力学模型 → Gazebo/ROS 2 → C++ 控制器 → Sim2Sim → MCU 控制程序 → CAN 通信。控制器不能与某一个仿真器强耦合。控制部署可选纯上位机、上下位机联合或纯下位机三种模式，均须说明遥控器输入、订阅 Topic、CAN/串口链路和急停策略；协议见 [`remote_control.md`](remote_control.md)。

## 3. 通用验收标准

- CAD、URDF、RViz/Gazebo 中的关节、尺寸、轮径、质量和惯量一致。
- 机器人能够前进、后退、左转、右转，并通过压缩、蓄力、伸展、离地、空中、落地完成跳跃动作；键盘或模拟 Web 页面可以作为演示遥控器。
- 核心控制逻辑使用 C++；Python 只能用于分析、绘图、数据处理和辅助测试。
- Ubuntu 22.04 中存在 `wheelleg` 用户和用户组，能够访问 USB/串口、摄像头、GPIO、`can0` 或 `vcan0`。
- MCU 能读取 IMU，接收上位机控制帧并发送状态帧，Linux 与 MCU 之间形成可演示的闭环；纯下位机方案可独立完成控制并将仿真/虚拟执行器部署到下位机。
- Git 历史能够反映真实开发过程；多人协作必须使用个人分支和 Pull Request。

## 4. 总分

总分 100 分：机械 15、URDF 10、ROS 2 + 仿真 20、C++ 控制器 10、Linux 10、MCU + IMU 10、CAN 10、Git/GitHub 10、工程文档 5。另设最高 10 分 Bonus。

## 5. 严重扣分

一次性上传全部内容、使用他人代码不注明、机械模型与 URDF 不一致、核心控制使用 Python、没有 Sim2Sim、模块缺少对应 Git 历史，均按实际影响扣除大量分数；其中 Python 替代 C++ 时，C++ 控制器原则上不得分。

## 6. 最终演示

至少演示：CAD 装配与四连杆运动、URDF 在 RViz 中显示、Gazebo 五种运动、Linux 权限检查、IMU→MCU→CAN→Linux，以及 Commit/Branch/PR/Tag/Release。
